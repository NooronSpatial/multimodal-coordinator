**How the capture was made.** The row
`MLXPlainPromptTests` · "no table on the call, none on the generator:
the prompt is the bytes captured before 4z", run once with
`MMK_CAPTURE_PROMPT` pointing at the file:

```bash
export MMK_MLX_MODEL=~/.cache/huggingface/hub/models--mlx-community--Qwen3-0.6B-4bit/snapshots/73e3e38d981303bc594367cd910ea6eb48349da8
MMK_CAPTURE_PROMPT=$PWD/docs/evidence/4z/plain-prompt-before.txt swift test --filter MLXPlainPromptTests
# … piece 2's MLX changes …
MMK_CAPTURE_PROMPT=$PWD/docs/evidence/4z/plain-prompt-after.txt swift test --filter MLXPlainPromptTests
cmp docs/evidence/4z/plain-prompt-before.txt docs/evidence/4z/plain-prompt-after.txt
```

Without `MMK_CAPTURE_PROMPT` the same row COMPARES a fresh render
against both files, and the files against each other, and is red on
any byte that moved. Without `MMK_MLX_MODEL` it prints `SKIPPED (no
MMK_MLX_MODEL …)`, as every live MLX row does in CI.

**How to read a green.** A run WITH `MMK_CAPTURE_PROMPT` set ends
"passed" having compared NOTHING — it wrote a file and printed
`CAPTURED … this run compared nothing`. Only a run without that
variable, with the model, is AC-272's proof; a green log that carries
the CAPTURED line is not one.
