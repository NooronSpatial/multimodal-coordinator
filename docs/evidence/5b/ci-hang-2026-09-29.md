# A CI run that never finished — 2026-09-29, run 36579409889 (commit 02c09f6, piece R)

**What happened.** The job built with warnings as errors, entered "Test (the
suite, minus the hammer)", printed its last line at 14:11:43, and then printed
nothing until it was cancelled by hand at 14:23:27 — twelve minutes of silence
in a step that takes about three. No one-minute time limit reported anything.
Raw log: `ci-hang-2026-09-29-run-36579409889.log`.

**What the log can and cannot say.** 34 tests have a "started" line and no
end — from many unrelated suites (downloads, the voice lead, the coordinator's
interruption rows, Retirable, and 5b's own). But hundreds of lines share one
timestamp (14:11:43.88…): the test process's output reached the runner in
buffered blocks, so the list is where the last FLUSH was, not where the process
stopped. The honest reading is narrower: the process never exited, and its
last output block was written at 14:11:43.

**What was checked.**

| check | result |
|---|---|
| the next CI run, on a SUPERSET commit (b823003: piece R + 3b) | passed, 9 m 52 s |
| the whole suite locally with a ONE-thread cooperative pool (`LIBDISPATCH_COOPERATIVE_POOL_STRICT=1`) — any task blocking a thread while it waits on another task deadlocks there | 969 tests passed in 23 s — `strict-pool-2026-09-29-one-thread.log` |
| the same commit re-run on CI | see below (appended when it ends) |

**What it is not, so far.** Not a thread-pool deadlock that shows under a
one-thread pool; not reproduced on the next run. **What it may be:** one test
that awaits something its time limit cannot cancel — mutation M32 in piece 4
showed this exact shape in a test helper of this milestone (a task group
waiting on a waiter nobody answers), which was fixed; a pre-existing row with
the same shape would hang a run the same way.

**Owed.** The 20× loop before the PR, with every failing log kept; a
recurrence gets its own entry here. A CI job-level `timeout-minutes` would
stop a hang from burning the runner for six hours (it happened twice before,
see the memory of 4y) — recommended to Ryad, not changed here: CI's
configuration is his call.
