## What the library reads in it

```
 turn N: the model finishes the whole reply ──▶ the session is KEPT (D-117 F-10 A)
         the person speaks over it while it is being SPOKEN
         the memory writes what was HEARD, marked interrupted
 turn N+1: the session holds the whole reply, the memory holds the cut one
           ──▶ they do not match ──▶ a new session, seeded from the memory
               mindSessionSeeded(.memoryChanged, turns: …)
```

- **`memoryChanged`, not `lastAnswerUnfinished`.** A barge while the model
  was still WRITING would have said `lastAnswerUnfinished` (the keeper's
  `ended(_:by:)`). `memoryChanged` means the model had finished and the
  speech was cut: the memory keeps what was heard, the kept session held
  the whole reply, and the two no longer agree (`SessionKeeper`'s keep
  decision; `SessionSeedReason.memoryChanged`'s doc names this very case).
  This is the rule as built — AC-306, D-117 F-10 A, the window rule
  (D-118 F-12 C).
- **`turns: 1` on both is the memory's second bound**, not a lost turn:
  `ConversationMemory` keeps at most 600 characters by default (it may
  overshoot by the newest exchange alone), so with long replies only the
  newest exchange fits. Read from the code; the diet app's own bound was
  not asked.
- **4 306 and 3 977 ms are re-seeded turns** — the path from before 5b,
  plus one and two tool rounds. They are not AC-315's number, which is
  turn two's first token on a KEPT session, against 3.4 s.
- **Tools:** called when asked on both visible turns. One tool nobody asked
  for (`read_rule`, before `tick_meal`) — the model's choice, and a read,
  not a write.
- **No retry fired:** no unnamed failure in this conversation.

## What it shows beyond AC-315

The diet app's point is right, and it is the rule as built: every turn
that follows a cut reply starts a new session and pays the prefill again
(INSTRUMENTS §71: 8 644 fixed characters, before the remembered turns). A
long reply invites a barge, so the saving depends on short replies. The
diet app is making its replies shorter.
